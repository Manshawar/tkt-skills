# Implement 阶段

调用 `/implement` 时，遵守以下纪律：

1. **最小化实现**: 只实现当前需求，不预支未来。
2. **机器可验证闭环**: 实现前先定义可运行的验证方式（测试/命令/脚本）。
3. **事后减法**: 功能跑通后，问"哪些代码可以删? 哪些抽象本次用不到?"
4. **复用优先**: 优先使用项目现有的工具函数和依赖。

## 无测试项目的测试生成时机

| 场景 | 生成时机 |
|---|---|
| 新功能 | 实现前或实现中生成 |
| 修 bug | 修复后补回归测试 |
| 重构 | 重构前补行为测试 |
| 纯样式/文档 | 不生成 |

## 相关命令

- 拆任务: `/to-tickets`

- 评审: `/code-review`
- 验收: `/tkt-socratic`
