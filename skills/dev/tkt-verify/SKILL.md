# tkt-verify

IRON LAW: 截图必须给人看,禁止只说「验证通过」。人对截图说「成功/确认」才算过;截图落约定路径 `~/.config/tkt/verify/<项目>/`,一个功能点一个子目录,skill 自管「保留最近5个目录」。

**自包含**:skill 独立完成全流程(操作/截图/写描述/剪轮),不依赖 tkt 平台;平台只是读这个目录做展示,没有平台也能用。

**分工**:本 skill 只做日常验证(快、免费、当场确认)。要沉淀防回归用例 → 攒一批**已稳定**的改动(页面结构近几次提交没再变 + 已用本 skill 验过)后用 `/tkt-test-gen`,别在这里生成 spec。test-gen 的触发锚点是「稳定」,不是「做完」。

## Workflow

```
tkt-verify Progress:

- [ ] Step 1: 定范围 ⚠️ REQUIRED
  - [ ] 1.1 确认验什么(本次改动哪件 + 操作后必须看见什么)
- [ ] Step 2: 起被测页 ⛔ BLOCKING
  - [ ] 2.1 确认服务在跑/路由可达;不可达先报,不硬探
- [ ] Step 3: agent-browser 操作 ⚠️ REQUIRED
  - [ ] 3.1 新建本轮子目录 ~/.config/tkt/verify/<项目>/verify-<ts>/(一个功能点一个目录)
  - [ ] 3.2 操作前截图
  - [ ] 3.3 执行操作(snapshot -i 拿真实结构,禁止猜 DOM)
  - [ ] 3.4 操作后截图(复杂交互中段也截)
  - [ ] 3.5 写 desc.md(验证点/操作/期望 + 每张图一句话)
- [ ] Step 4: 输出 + 人确认 ⚠️ REQUIRED ⛔ 无人确认不算完
  - [ ] 4.1 输出简单叙述 + 目录路径(用户去看图)
  - [ ] 4.2 等用户判断
- [ ] Step 5: 剪轮 ⚠️ REQUIRED
  - [ ] 5.1 按 ts 倒序留最近 5 个 verify-* 目录,更老的整个删
```

## Step 1: 定范围 ⚠️ REQUIRED

一句话锁定:验本次改动的哪件;操作后用户**必须看见什么**(文案/选中态/列表变化/条件区块出现)。

改动来源:有本轮对话 → 直接归纳;新会话只丢一句「验一下 X」→ `git status` + `git diff --stat` 扫名单聚类,但仍问用户验哪件。

开放题就问,别替用户定。多件改动默认一件件验,不合并成一次大遍历。

## Step 2: 起被测页 ⛔ BLOCKING

- 需要 dev 服务先确认在跑(端口/路由);被测页进不去(服务没起/角色无权限/缺前置数据)→ 如实报卡点,禁止伪造入口蒙混
- 动态路由项目:目标页被守卫弹回 = 当前角色无权限,换 `?role=xx` 或有权限账号再探,别在错角色下反复试

卡点报告格式:`卡点: <哪一步进不去> + 原因 + 需要用户提供什么`(如「进不去 /test:当前角色无权限,路由被守卫弹回 /HMMain;需要 `?role=1` 或有权限账号」)

## Step 3: agent-browser 操作 ⚠️ REQUIRED

```
agent-browser open <url> → snapshot -i → 按真实 ref 操作 → screenshot
```

- **截图路径**:一个功能点一个子目录 `~/.config/tkt/verify/<项目>/verify-<ts>/`,`<项目>` = `basename $(git rev-parse --show-toplevel)`。前后截图都放该轮目录里。**AI 不 Read 截图**,用户自己去看
- **操作前截图**:记录初始态
- **操作**:优先 `snapshot -i` 的 `@eN` ref / 稳定选择器;禁止凭源码猜 DOM(结构常与推断不符)
- **操作后截图**:捕获结果态;列表顺序变化/多步状态切换这类,中段也截一张
- **desc.md**:写进本轮目录,三行 + 图注:

```
验证: <功能点>
操作: <做了什么>
期望: 操作后应看见 <X>
图: before=<初始态> after=<结果态一句话>
```

desc 只写「图是什么」事实,**不写「是否成功」**(成功是用户的判断,不是 AI 的)。

## Step 4: 输出 + 人确认 ⚠️ REQUIRED ⛔

输出格式(简单叙述 + 目录,用户去看图):

```
验证: <本次改动的哪件>
操作: <做了什么>
期望: 操作后应该看见 <X>
目录: ~/.config/tkt/verify/<项目>/verify-<ts>/
  before-<n>.png  <初始态一句话>
  after-<n>.png   <结果态一句话>
请确认: 成功 / 有问题(说现象)
```

**人对截图说成功才算过。** 用户没回或有异议 → 按现象再验,别急着换方向。没平台也能用——用户直接打开目录看图。

## Step 5: 剪轮 ⚠️ REQUIRED

每次验证完(无论人确认结果如何),按 `<ts>` 倒序留最近 5 个 `verify-*` 目录,更老的**整个目录**删掉(一组图全留或全删,不留残组)。剪的是目录不是单图。

## Anti-Patterns

- 验证完只说「通过/没问题」不贴图(人证纪律失效)
- 从源码猜 DOM / 凭文案盲点击;跳过 snapshot -i
- 替用户判断成功(用户没确认就往下走);desc 里写「验证通过」这类结论(成功是用户定的)
- 在这里生成 spec/cases.json(攒批 e2e 是 tkt-test-gen 的活)
- 依赖 tkt 平台收图/剪轮(skill 自管剪到 5 个目录,没平台也要能用);剪单图不留整组(留 5 个目录,按目录整个删)
- 被测页进不去还硬探(角色守卫弹回当页面坏了排查)
- 一次遍历多件改动(一件件验,人一件件确认)

## Pre-Delivery Checklist

- [ ] 截图已落 `~/.config/tkt/verify/<项目>/verify-<ts>/` 且 desc.md 已写,目录路径已给用户,用户已确认(或已如实报卡点)
- [ ] 期望值是用户可见结果,不是「断言通过」;desc 只写事实未写「成功」结论
- [ ] 操作来自 snapshot 真实结构,无猜 DOM
- [ ] 已剪轮:倒序留最近 5 个 verify-* 目录,更老整个删;未生成 spec
