# tkt-test-gen

IRON LAW: 生成的用例必须「像用户一样操作,验证用户可见结果」——能回答「它防住这次改动的哪个回归 / 验证哪个功能」。与改动无关的通用断言(「标题可见」「页面能打开」)是废品。草稿必须人确认后才写回 spec/cases.json。**用例禁止触发平台自身 run(点「冒烟/全量/分组」按钮),会死循环跑崩机器。**

**验收方向由人定,不是由 diff 文件数定。** 读完改动先给出 3~5 个「主验收点」选项,**停下让用户多选**。没选定禁止整页探测/写矩阵。整页重枚举只适用于用户勾选了「该页交互模型变了」的页面;全站 token/主题扫了很多文件 ≠ 那些页的旧操作流全测一遍。

**功能点矩阵是完成门,报告留证不是。** 矩阵只覆盖**已选定**的验收方向。探测到的每个可交互点必须拆成该拆的行(存在 / 操作 / 直达 / 条件展示),每行在 cases.json 有对应测试点,不测的写原因(含「用户未选」)。已有页面重构/加交互 = 当新页面重枚举,不能只补一条基线——但前提是用户把该页选进了验收方向。

**判覆盖**:用例的断言必须直接验证该行的用户可见结果。基线 `toBeVisible` 只覆盖「存在」行;另一条用例的前置 click/goto 不算覆盖;测工作台不自动覆盖点选详情。

**入库范围** = 矩阵里「缺口」且没有不测原因的全部草稿。默认全部入库;用户只能删减,不能用「基线已经有按钮」把操作/直达踢出范围。`覆盖率` 先看功能点,再看 midscene 报告留证。

## Step 0: 前置检查 e2e/ ⚠️ REQUIRED

生成用例前先确认项目已初始化 e2e/。检查 `e2e/` 目录是否含 `playwright.config.ts` + `fixture.ts` + `cases.json`。

- 已初始化 → 继续 Step 1
- **未初始化 → 停下,引导先 `/tkt-e2e-init`**,不硬写 spec(新项目必须先 init 生成骨架 + 装依赖 + 配 MIDSCENE_MODEL_*)

## Step 1: 收集(读代码 + 探测)⚠️ REQUIRED

先读改动,再**用 agent-browser 探测真实页面**,不猜。

读 diff 回答三个问题:
1. **改了哪些文件** —— 组件/页面/样式/逻辑?
2. **改动本质** —— 修 bug、加功能、调样式、改交互? **按本质聚类,不按文件清单摊开。**
3. **渲染结果变在哪** —— 用户打开页面后哪里不一样了?

### 1.2b 验收方向 ⛔ BLOCKING

读完 diff **先出选项、停下问用户**,禁止直接开整页矩阵。选项 3~5 个,可多选:

```
这次改动本质: <一句话>

请选本次验收方向(可多选):
A. <主变化> — 测:<用户操作+可见结果> / 不测:<易跑偏的旧交互> 【推荐】
B. <次要但相关>
C. <diff 扫到、但不是主变化的旧页交互> — 默认不推荐
D. 其他:你指定
```

聚类规则:
- 全局 chrome(主题开关、shell 顶栏)单独成项,不要并进某个业务页
- 很多页只换了 token/class → 选项是「切主题 + 抽检一两页观感」,不是「每个被扫到的页整页重测」
- 交互模型变了(新控件、排序逻辑、信息架构)→ 才给「该页整页重枚举」选项
- 主变化必须出现在选项里;禁止用旧页操作流顶替主变化

用户选定后,1.3 只探选定方向的路由和控件。未选项在矩阵里写「本次不测:用户未选」。

**禁止**:没问就整页重枚举;主验收点不在矩阵里就进 3.2;为迁就 `aiAssert` 锁死本次要验的状态(做主题却 `beforeEach` 写死 dark)。

探测目标页(仅选定方向涉及的路由):
```bash
agent-browser open <url>          # 打开被测页
agent-browser snapshot -i          # 拿真实元素(按钮文案/href/输入框占位/标题/状态)
```

**探测产出两份,缺一不可**:
1. **稳定定位依据** —— 断言只建立在探测到的元素上,探测不到/不确定就标记待探测,不猜。教训:`aiTap('"测试" 工具卡片')` 会误点「测速」(文本歧义);改 `a[href="/test"]` 稳定定位一次通过。
2. **功能点清单(分列,一个控件可能多行)** —— 不要「一个按钮一行」了事:
   - **存在**:snapshot 里能看见(按钮/链接/输入)
   - **操作**:点/切/填了页面结果会变(排序变序、点选出详情、打开工作台)
   - **直达**:读代码里的 `searchParams` / `replaceState`(如 `?project=` `?case=`)。URL 不在 snapshot 里,漏读代码就会丢
   - **条件展示**:有数据才出现的控件(有 HTML 才有「工作台」)

选定方向涉及的每个路由都要探测(如勾了报告页才探 `/test` + `/test/report` + `/test/report/full`)。diff 里改过样式的页,若用户没选,不探、不进矩阵。

## Step 2: 读项目现有 e2e/ 对齐 ⚠️ REQUIRED

Load `references/whitebox-flow.md` for 目录结构、功能清单驱动、断言写法。

- 目录按内容:smoke(冒烟基线)、platform(平台页)、manual(手动/触发 run 独立验证,不进平台 run)
- **cases.json:group = 功能域,不是执行粒度**。group 是「页面 + 关联页面」组成的完整功能(如 `首页`、`测试平台`),交叉引用:页面 + 它操作到的关联页面/功能。**冒烟/全量是执行粒度,不放进 group**:
  - **冒烟** = 本次提交/工作涉及功能的**全部用例**(diff 驱动:改了什么跑什么,不只 P0,含 P1)。如一次工作做了「删除+改样式」,冒烟就跑删除+样式相关全部用例
  - **全量** = 所有功能域的全部用例(scope=all,把累积的功能域合成一组全跑,18 条 = 首页 + 测试平台全过)
  - **分组按钮** = 单功能域(中间粒度,单独测某个功能域)
  - 冒烟 ⊂ 全量(冒烟是 diff 命中子集,全量是所有用例;全量恒 ≥ 冒烟)
  - priority 是用例质量分层,不是冒烟/全量依据:P0 = 确定性断言(快);P1 = aiQuery/aiAssert 深层回归

## Step 3: 生成草稿 ⚠️ REQUIRED

Load `references/whitebox-flow.md`(操作流写法)+ `references/midscene-api.md`(API 全貌 + 留证)。

**3.1 功能点矩阵(完成门,先于写草稿)**:把 Step 1.3 的清单和现有 cases.json 逐行对照,输出表:

```
功能点 | 类型(存在/操作/直达/条件展示) | 页面 | 已有用例 | 缺口/不测原因
```

- **新页面、已有页重构、加交互**:仅当验收方向包含该页「交互模型变化」时,整页(含关联路由)重枚举;不能只测 diff 里那一块、也不能用一条「标题可见」顶整页。纯 token/主题换色、用户没勾该页 → 不自动整页重枚举。
- 每个可交互点按类型拆行:排序按钮 = 「存在」一行 + 「切换结果」一行;`?case=` 单独一行直达。
- **判已覆盖**(必须同时满足):cases.json 有用例,且该用例的断言直接验证这一行的用户可见结果。
- **不算覆盖**:基线里对同一按钮 `toBeVisible`;另一条用例的前置 click/goto;测了关联功能但没断言本行(点测试点只为打开工作台,没断言右侧描述/最近测试)。
- 不测原因只允许:用户未选该方向、防递归(点冒烟/全量/分组)、纯装饰、已标注的环境数据依赖。禁止写「基线已经有这个按钮」。禁止用「用户未选」盖住已选定方向里的操作/直达行。
- 矩阵有缺口才进入 3.2;没有矩阵就生成草稿 = 违规。

**入库范围** = 表中「缺口」且「不测原因」为空的全部行 → 3.2 每行一条草稿。默认整份入库,用户可删减,不能把操作/直达行改成「已有基线」蒙混。

每条草稿格式(不写回):

```
用例名: <描述性,对齐现有 spec>
防回归/验证: <这次改动的哪个具体变化/功能>
操作流: <导航→点击→输入→发送 步骤>
断言: <expect(...) 或 aiQuery(...) 或 aiAssert('...')>
group / priority / desc: <group=功能域(页面+关联页面,不写冒烟/全量), priority=P0确定性/P1深层, 对齐 cases.json>
files: <用例断言的源码 glob,如 web/src/pages/test.tsx 或 web/src/pages/*.tsx>
spec: <用例所在 spec 文件名,如 test-platform.spec.ts(改该 spec 文件冒烟跑该 spec 全部用例)>
```

**files 登记(diff 选例地基)**:每条用例登记它断言的源码文件 glob——改了这些文件,冒烟(diff 驱动)就跑这条用例。粒度:目录级起步(`web/src/pages/*.tsx`),断言精确文案的精确到文件(`web/src/pages/test.tsx`)。纯文档/注释不登记(无关联改动跳过)。

**spec 登记**:每条用例登记它所在的 spec 文件名(如 `test-platform.spec.ts`)——改了该 spec 文件(断言/操作流变了),冒烟跑该 spec 的全部用例。同 spec 的多条用例登记同一个 spec 值。

**操作流优先,断言抓结果**:像用户一样走(点新增按钮→填输入框→发送→看结果)。关键功能用 `aiQuery` 提取数据 + `expect`(可靠 + 生成报告),不押在单一 `aiAssert` 视觉判断上(有非确定性)。确定性断言保留(快速红绿),`aiQuery`/`aiAssert` 补上留证(报告可审阅功能)。

**留证判定(硬规则,生成时逐条过)**:**操作流用例必须留证**——导航/点击/切换/输入等「用户操作行为」,绿了只证明结果对,过程不可审阅;必须在操作后加 `aiQuery`(提取结果数据+expect)或 `aiAssert`(视觉),生成带截图报告。数据渲染/条件展示类(读列表/历史/状态展示)可纯 `expect`(不调 midscene,无报告是合理的)。P0 确定性基线(标题/卡片/按钮存在)纯 `expect` 即可。**判断口诀:「这条用例有『操作』吗?有 → 必须留证;只是『读数据看结果』→ expect 够」**。

## Step 4: 人确认入库范围 ⚠️ REQUIRED

先出示矩阵(只含已选定方向),再出示**入库范围**(缺口且无不测原因的草稿清单)。问:全部入库?删哪几条?改断言/分层?只看不写?

未确认禁止写回。不要把入库范围理解成「随便选几条喜欢的」——范围由**已选定方向的矩阵**推导,确认只是签字或删减。Step 4 不再重新讨论验收方向;方向在 1.2b 已经锁死。

## Step 5: 写回 spec + cases.json

- 按目录 append 到现有 spec(或按结构新建),不覆盖
- cases.json 补 group/priority/desc/files,不破坏 JSON、不与现有键冲突
- 保持 fixture import 结构不变

## Step 6: 跑 + 修复(agent 代跑,不要丢命令给用户)

写回后 **自己跑完**,不要只输出验证命令等人执行。Load `references/whitebox-flow.md`「跑 + 修复」。

**cwd 铁律**:在 `<项目>/e2e/` 执行(或仓库根 `pnpm --dir e2e exec playwright test ...`)。仓库根 `npx playwright` 会打到另一份 `@playwright/test`,假报 `beforeEach` + `No tests found`(coverage-review 3.0)。

**跑哪些**:
- 默认:只跑本次入库范围。`-g` 用不含 `/` `?` 的子串;多条可用 `-g "A|B|C"`(PowerShell 务必给 grep 加引号)
- 用户明确说「全跑完 / 验收 / 跑这个 spec」→ 跑该 spec 整文件(`playwright test platform/foo.spec.ts`),仍禁止点 UI「冒烟/全量/分组」
- 禁止:没被要求就无过滤全仓库试错;禁止点平台 run 按钮(会死循环)

红了读失败理由/截图修,同一条重跑 ≤3 次。

跑完后 **Load `references/coverage-review.md` 做两层覆盖率评估**(⚠️ 强制收尾):
1. **功能点覆盖率**:snapshot 清单 × cases.json(矩阵缺口=没完成)
2. **报告覆盖率**:`ls e2e/midscene_run/report/` 对照 cases.json,操作流该有报告的都有

只报报告覆盖率、跳过功能点矩阵 = 没完成。发现操作流用例无报告 = 留证缺口 → 补 `aiQuery`/`aiAssert` 重跑。输出 `功能点覆盖率 A/B` + `报告覆盖率 N/M` + 两份缺口清单。

## Anti-Patterns

- 猜 DOM/文本,不 agent-browser 探测
- `aiTap` 用自然语言猜文本(「测试/测速」歧义),不用稳定定位
- 关键功能押在单一 `aiAssert` 视觉判断(非确定性),不用 `aiQuery`+`expect`
- 操作流用例纯 `expect` 不 `aiQuery`/`aiAssert` 留证(绿了但过程不可审阅)
- **用例触发平台自身 run(点冒烟/全量/分组),死循环跑崩机器**
- 只丢验证命令不代跑;或没被要求就无过滤全仓库试错
- 在仓库根 `npx playwright`(两份 @playwright/test,假报 beforeEach)
- 测试绿了就以为完成,不核对「功能清单全枚举」
- **用报告覆盖率代替功能点覆盖率**(midscene HTML 齐了,但排序/点选/直达/工作台等可交互点没有用例)
- **没问验收方向就整页重枚举**(diff 扫到很多页就把那些页旧操作流全测一遍)
- **主验收点被旧页交互顶替**(做主题却只测排序/点选;做报告页重构却只测标题)
- **锁死本次要验的状态**(主题工作 `beforeEach` 写死 dark,白天模式永远测不到)
- **已有页面重构只补基线**(「标题可见」顶整页;Step 3.1 写「新页面才全枚举」)
- **基线 toBeVisible 当成操作流已覆盖**(排序按钮在 ≠ 点了会变序)
- **别的用例前置步骤当成覆盖**(工作台测试点了一下测试点 ≠ 点选详情已测;`goto` 带 query ≠ 直达已测,除非断言了选中结果)
- snapshot 只当选择器、不当覆盖清单;URL 直达不读代码(snapshot 里没有 `?case=`)
- 把入库范围理解成「挑选几条写」而不是「矩阵缺口全部入库」
- group 用「冒烟/回归」命名(冒烟/全量是执行粒度,不是分组;group 必须是功能域)
- 生成通用断言(「标题可见」「页面能打开」)
- 未确认就写回 spec/cases.json
- 跑前手动清 `midscene_run/report/`(报告不去重不删除,文件名带时间戳天然不重名,平台归档取最新;手动清破坏历史)

## Pre-Delivery Checklist

- [ ] 每条用例能回答「防哪个回归 / 验证哪个功能」
- [ ] 白盒定位(稳定选择器),非 AI 猜文本
- [ ] 关键功能用 `aiQuery`+`expect` 留证(生成报告可审阅)
- [ ] 用例不触发平台自身 run
- [ ] 验收方向已经用户选定;矩阵只覆盖选定方向;未选方向标明「用户未选」
- [ ] 功能点矩阵已输出;存在/操作/直达/条件展示已拆行;判覆盖未用基线或前置步骤顶替
- [ ] 入库范围 = 矩阵缺口且无不测原因;经用户确认才写回
