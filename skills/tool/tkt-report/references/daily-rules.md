# 日报正文规则（agent 写 items/sheetTime 的硬约束）

由 tkt-report skill 加载。采集数据来自 `tkt report gather` 的 JSON 输出。

## Iron Law

- 不编造模块名、PR 号、客户名、路径（素材与用户补充未出现的专名一律不用）。
- commits 是线索与证据，**时间戳仅参考**；工时可自由拉伸以对齐 targetHours，不按提交时刻机械切分。
- 逐条评估 hours 合理性：与事项难度/范围匹配；禁止整点灌水、过碎拆分、一眼假的匀摊。
- 可补单人可闭环配套工作（排查/自测/梳理/文档/小改），须贴合当日素材或项目方向，编得不出破绽。
- **禁止**虚构与同事交互：开会、联调等待、请人确认、跨人指派/review 等（用户补充或画像明示除外）。
- 禁止自动补：晨会/周会/整理清单/跟进 bug（除非用户补充明示或画像允许）。
- 不清楚的细节：不要硬编；宁可少写专名、把不确定留给用户补充，不要输出需他人配合的条目。

## Profile

- gather 输出的 `profile` 字段含 Identity / Scenario 画像块：**严格遵守**；与规则冲突时以用户追加画像为准，底板与 Iron Law 垫底。

## 素材采集

- 数据一律来自 `tkt report gather` 输出；用户口头给出**本地仓库路径**且不在 repos 时，先用 `tkt report gather <路径>` 显式采集并重新取输出，再写正文。
- 不是 git 的路径 gather 会报错，不编造该路径内容。

## 规则

1. items 条数按当日实际工作量浮动（一般 3~8 条），不凑数、不硬凑满；宁可合并同类，禁止拆成一堆碎点。
2. items.hours 之和须对齐 targetHours（弹性上班按 09:00 起算 → 写日报时刻为下班）；禁止按多仓累加拉长。
3. 单条 hours ∈ [0.5, 4]，0.5 粒度；分配前自检每条是否站得住脚。
4. 改写 commit：去 feat:/fix: 前缀；动词开头；业务中文（除非画像要求其它语言）。
5. text 不含【项目】与「- X小时」。
6. project 必须用各仓中文 display_name（gather 里 `repos[].project`）；禁止用英文仓库名。
7. sheetTime：单行 ≤80 字；无【】、无「小时」、无换行；用；连接。
8. 缺口填充须符合画像；无 commit 时用【通用】或已知 project，勿编具体模块。填充只能用单人可闭环的事。
9. 用户补充的杂事必须写入 items。

## 输出

```json
{"items":[{"project":"项目","text":"动作对象、补充","hours":1.5}],"sheetTime":"概括甲；概括乙"}
```

以上 JSON 经 `tkt report save` 校验后归档。
